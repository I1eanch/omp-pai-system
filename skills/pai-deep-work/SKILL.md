# PAI Deep Work

Use this skill for complex, ambiguous, multi-file, investigative, design, refactoring, or implementation work.

## Operating contract

1. Establish the requested outcome, scope boundaries, constraints, and observable success signals from the conversation and repository evidence.
2. Research existing conventions before editing. Use OMP symbol-aware and syntax-aware tools where available.
3. For three or more steps, use OMP native todo or goal state. Do not create a parallel ritual progress system.
4. Load only relevant TELOS or MEMORY records through PAI tools. Missing context remains missing; never synthesize personal facts.
5. Decompose work by real dependencies. Delegate only when the user or active harness policy permits it and slices are genuinely independent.
6. Fix the source of a problem, migrate every affected caller, and remove obsolete paths without compatibility shims unless compatibility is an explicit requirement.
7. Verify the changed behavior using the actual program path. Tests support permanent contracts but do not replace a smoke test.
8. Report the result, exact verification evidence, and any concrete residual risk concisely.

## Persistent work records

A persistent PRD is optional, not a phase ritual. Create one only when the work must survive session boundaries or the user explicitly requests a durable specification. Store it under the configured MEMORY root and keep its registry synchronized through the PAI PRD tool.

## Prohibitions

- Do not print PAI mode banners, fixed TASK lines, hidden reasoning, or ceremonial phase output.
- Do not contact voice, TTS, notification, analytics, or telemetry services.
- Do not invoke tools or agents merely to satisfy a quota.
- Do not impose time budgets or criterion-count floors that the user did not request.
- Do not read the entire MEMORY, TELOS, or skill corpus when a focused query suffices.
